# Army QR aggregate publication

The public `/army` page reads aggregate guild observations without signing in or installing a companion. Missing guilds are unavailable, never zero. The page does not load the member application's boot data or private member APIs.

The separate `/army/report` page admits current authorized reporters. The first implementation permits current site administrators only. It does not infer reporting permission from an organizer title, a character name or an appointment. Adding another reporter needs a separately reviewed identity rule.

An attended scan uses the separate `OLCS2` aggregate protocol and `/ogarmy` command. The existing identity QR protocols and the original local `OLCS1` pilot remain unchanged. The original local 30-second deadline includes the normal source picker and every QR part. Both the wall and monotonic clocks, matching nonce, complete-part checks, image bounds, masking, original source ages and source-interruption refusal remain. A checksum does not prove game origin or truth.

Raw QR frames, pictures, video, member names, notes and game account identities never enter an Army API request. Capture is local. Only the strict aggregate snapshot is sent when the reporter chooses **Prepare private preview**. The server preview is not publication. After reviewing its canonical figures, the reporter must explicitly consent and choose **Publish snapshot publicly**.

Figures count reported characters, not people. Class, level-band and rank-position distributions are withheld whole if any small or unavailable bucket could expose a small remainder. Rank positions have no authority on the website. Observations prove neither membership nor complete coverage of Olympus, and rereading or publishing them cannot refresh their original game timestamps.

Only Olympus guild names and Alliance reports are eligible. The reporter's raw game realm label stays on that device. Before any aggregate API request the browser replaces it with the owner's fixed publication identifier, **World of Warcraft: Forever PvE**, and the separate public-consent checkbox requires the reporter to attest that actual scope. This attestation and identifier substitution do not prove the game realm or source. No arbitrary free-text realm label is uploaded or stored.

A publication whose answer is lost keeps only its original aggregate and preview token in volatile tab memory for **Check original publication outcome**. This checks whether that exact snapshot is current; it does not prove which reporter wrote it or establish that an earlier request wrote a superseded report. It does not retry, create a replacement request or publish in the background. Hiding, clearing or closing stops capture and clears unpublished review; this does not withdraw an already published report or recall copies made by readers. Closing the tab loses that original recovery view. There is no public-data deletion or withdrawal action in this change.

The publisher page alone permits camera and window capture. Microphone, geolocation, payment, USB and framing remain unavailable. Global member-site headers, production configuration, settings, feature flags, schema, Native E2, member admission, identity verification and launch gates retain their existing rules. No companion, LAN listener, watcher, filesystem reader or background capture is introduced.

Desktop and mobile viewport checks use synthetic aggregates, with empty, masked and populated states plus the ordinary preview/consent/publication flow and original-outcome recovery. They are distinct from an actual game capture or a physical phone-camera test. No live production observation is required for those checks.

Each accepted exact guild name has its own storage slot: Olympus and Olympus I through Olympus X are eleven distinct identifiers. Neither label aliases another. A report for one guild cannot replace another guild's report.
