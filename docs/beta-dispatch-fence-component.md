# Beta dispatch fence: discovery and legacy-grant component

This source component adds no seal issuer, route, installation, activation or role-reuse authority. It builds on the exact catalogue transition in `dispatch-seal-profile-transition.md`. No deployment configuration enables it.

`BETA_RESET_DISPATCH_SEAL_MODE` has exactly two usable states: property absent is the existing behavior; an own data property equal to `v1` enables these dispatch restrictions. Every other present value, accessor or inherited property holds scoped new work. The descriptor is captured before the first await and checked again for each dispatch use. Changing it does not invalidate the shared policy/scan predicates used to record an already admitted response.

The scope remains the source-owned reset guild and twelve role IDs. A `betaResetDispatchSealV1` row of any value, including malformed JSON, makes the `v1` presence predicate false. There is no parser-based exemption. The absent-mode restriction function returns the original SQL string unchanged, adds no binds and adds no database/provider call. Original expiry, admission, policy and scan guards remain necessary in both modes.

The new predicate is consumed by the existing scan INSERT/UPDATE claim, page-current reads, observation INSERT and paired cursor UPDATE, selection, legacy-grant attempted INSERT and final pre-PUT proof, and legacy grant-compensation attempted INSERT. The compensation path includes an already-settled `legacy_put_acknowledged` parent with a lost ACK reply. The predicate is not added to response/unknown writes or the scan release path. A legitimate earlier claim remains spent; a late response is not canceled, retried or reinterpreted as provider drain.

The bulk-removal claim and final DELETE proof in `role-settlements.ts` are not converted here. Therefore `v1` completes allowed discovery but explicitly returns `beta_dispatch_effect_fence_pending` before delegating a role effect; status reports removals inactive. Absent mode retains the original delegation. Do not activate this partial component or issue a seal on the assumption that all writers have been fenced.

The remaining source integration includes all three other compensation producers (`compensateGrant`, `retireAttendedMembershipRole`, `retireOwnedMembershipRole`), queued-role and generic-removal creation/claims, pair claims, erasure-role effects, and the legacy direct removals in `roles.ts`, `roster.ts` and `interactions.ts`. A standalone seal read followed by a receipt-less DELETE does not close their race. Those files have separate ownership and are unchanged here.

There are still two distinct possible future seal predecessors: an exact retained V3 retirement, or genuine policy absence confirmed after cutoff in the eventual same-statement issuer CAS. This component creates neither. In particular, absent policy after cutoff is not changed into an armed policy, invented digest or retirement. Existing retirement/status inventory continues to use the exact original retained policy. `finalCompletion` and `roleReuseReady` stay false.

The eventual all-writer theorem requires real installed-source/barrier identity, atomic seal-versus-claim exclusion, retained original attempts/unknowns, and separate treatment of older receipt-less provider requests and restoration. A count, clock, GET, completed discovery pass or caller boolean cannot supply those premises. The setting alone is not an anti-restore trust anchor.

`worker/tests/beta_reset_dispatch_fence_test.cjs` is a new focused regression using the existing current-entry Native fixture, actual source and both catalogue layouts. It prepares positive grant/compensation/ACK cases and races at each new consumer, preserves absent-mode behavior, and checks invalid modes, malformed seal presence, honest predecessors and the explicit bulk-delegation hold. Test-only seal inserts do not model a production issuer. The test is not added to the aggregate by this component. At source handoff it is unexecuted: the shared runtime belongs to the genuine Claude run of the frozen composed checkpoint.
