## Minimum access and behavior

Only **GUILD_MEMBERS / Server Members** is needed for this directory. Keep Presence and Message Content disabled unless a separate approved feature establishes a need and the owner authorizes it. The Worker continues using signed HTTP interactions and the REST API. There is no Gateway connection, event subscription, message-content reader or presence/activity collection.

`GET /api/community/discord-directory` reads one source page of at most 1,000 Discord members per request and returns at most 100 eligible Olympus members. It projects only holders of the configured Olympus membership or current native-rank roles. When more eligible rows exist than fit the output, continuation starts after the last selected eligible member so no eligible row is skipped. It does not list the whole Asmongold server. The owner selected this narrower scope on 23 October 2026. An authenticated eligible Community reader may continue with its opaque, authenticated cursor for at most fifteen minutes from the original page. The cursor is bound to the original reader session, account incarnation, privacy generation, guild, page size and protocol version; a continuation never extends that deadline. It is not transferable to another account or guild. Discord pages are not an atomic snapshot: joins/departures during traversal can change what a later page returns. The UI must not call a partially loaded traversal complete or an unavailable response an empty directory.

The directory projects names, a bounded Discord CDN avatar, explicitly public configured Olympus membership/native-rank labels and current proven character links. A currently configured seasonal Treasury cosmetic role may add its title when that exact role is present in the current Discord response; it neither creates directory eligibility nor discloses a ledger amount. Safety, moderation and other private role IDs/labels are not disclosed. Bots and accounts still in membership screening are omitted. Discord membership is not proof of an Olympus in-game character or authority to grant any role. Verified character labels come only from existing keeper verification records for existing website accounts that pass current verification and privacy checks. Bot-verified members who never registered here can appear without a displayed character name. Unverified, denied, departed and self-claimed labels are not promoted to proof.

Eligible accounts are listed by default. The authenticated own visibility control, `GET`/`PUT /api/community/discord-directory/visibility`, accepts only the caller's `{listed:boolean}` preference. Opting out suppresses that account's entire directory row: display name, username, avatar, public role labels and proven character links. It requires no provider request and remains available without a current roster role. An own opt-out stores only the account ID and exact account incarnation in the existing private `site_settings` suppression map; listing again removes the entry. If the person cannot use the signed-in control, a current site administrator can record the exact account ID and requested preference after explicitly confirming that person's request, including for someone who never registered here. This attended entry uses only the exact finite Discord-only suppression marker, without creating an account or profile. The account's own copy includes only its preference, and registered erasure removes its exact entry. An incarnation-bound own preference does not transfer to a recreated account; an attended suppression remains effective until the person restores listing or an attended change/erasure removes it. Optional profile/profession/crafting information keeps its independent existing opt-in route; listing again does not opt into those details.

No new D1 objects, persistent Discord roster mirror, account creation, logging of member data, background enumeration, email, presence or message-content collection is introduced. Directory reads write no persistent state. Each response rechecks the original reader and each target's existing privacy/erasure standing and captured incarnation/generation after asynchronous work. An unavailable or revoked Discord entitlement returns an unavailable response; it never expands access or changes roles.

Portraits are direct, allowlisted Discord CDN images with no referrer and a local game-art fallback. Their URLs necessarily identify the selected Discord image; they are not claimed to be anonymous or to be copies hosted or erased by Olympus. The application retains no image bytes.

Account office associations stay in the existing appointed setting, with explicit publication consent, signed current-account or Discord-only proof and the existing exact-pointer erasure/withholding rules. An office association, directory result or approved intent is not a Discord permission, native rank, signing authority, reset authorization or Link activation.
