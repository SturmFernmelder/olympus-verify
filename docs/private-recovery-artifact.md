# Original private recovery artifact adapter

The two scripts in `worker/scripts/private-recovery-artifact-*` prepare or perform one attended original Wrangler operation against the fixed Olympus account and D1 database. They do not activate erasure, restore automatically, or grant Worker replay/open authority.

The existing CLI remains unchanged on disk. The observer checks its exact source bytes and applies seven count-one in-memory hooks to the original API request/response, export download, and import upload. It never receives authentication headers, opens an auth profile, or stores a signed download/upload URL. Original CLI output is suppressed because an error could include a bearer URL.

`--check <absolute-intent.json> <sha256>` validates the bounded intent and pinned source without provider requests or a secret read. `--execute-original-once` is the attended execution path. The intent must name an actual same-operation closing Floor/Gate tuple and its original 300-second interval; it cannot extend that interval. The existing release signing key is supplied only through `OLYMPUS_PRIVATE_RELEASE_SIGNING_KEY`. Its public key must equal the intent's existing accepted-release key. The child receives neither that key nor the control, recovery, gate, or cookie secrets.

The fixed target ledger spends before the original CLI starts. An incomplete attempt blocks later attempts even under another operation ID or output directory. A failed or missing reply remains unknown; the adapter never retries. The caller must run it under the already reviewed native Job containment and retain the actual original child/Job closure evidence. The script records only its known child closure and explicitly leaves all-descendant qualification false.

Supported operations are complete `d1 export`, private SQL import via `d1 execute --remote --file`, and timestamp-selected `d1 time-travel restore`. For Time Travel, the intent's `bookmark` field is the original Unix snapshot timestamp: the pinned CLI resolves it through the actual provider timestamp-to-bookmark API, then restores that exact returned bookmark. Bare bookmarks without an original timestamp observation hold. A raw `schema.sql` or initializer command is not an artifact input. Private imports require exact artifact bytes, SHA256, original metadata, and observed upload-stream SHA256/MD5 before the original ingestion completes. A provider upload-cache hit without that upload witness holds. Export verification waits for both the original download clone EOF and exact exclusive output-file readback. File size, identity and contents are checked around execution. Export size is an acceptance bound; the original export writer is not claimed to have a separately qualified concurrent disk quota.

The one existing pre-147 keeper is supported only through its exact original inventory hashes. That inventory never substitutes for a new import or Time Travel attempt. Future input artifacts require a verified signed original export receipt. No original keeper is rewritten, deleted, or copied by preparation.

The signed 25-field attempt binds the actual provider API EOF and returned bookmark, artifact identity where applicable, original cut/deadline, selected source and target epoch/profile, original CLI hash, original child and **original artifact/snapshot clock**. The 365-day copy-age check uses that original clock, including the keeper's hash-pinned original start time; a fresh restore never refreshes it. It is **not** accepted by the Worker as raw JSON authority. The optional private immutable service stores its exact signed bytes in `PRIVACY_IMMUTABLE_ARTIFACT_RECEIPT` and `PRIVACY_IMMUTABLE_ARTIFACT_SIGNATURE`, using the existing release verification key. It creates no key, signature or renewed timestamp.

The exact authenticated `install-and-reopen-artifact` command requires the source-owned observer to verify that receipt against the same accepted release, original cut, target epoch and actual post-restore Native profile/time. Only its opaque result can select `private_export` or `time_travel` suppression replay. The main transport and owner signer both whitelist this command with the existing ten-field body. Normal `install-and-reopen` remains the separate current-Native path and cannot silently fall back from a failed artifact observation. The per-resource replay identity includes the actual signed restore attempt; the old keeper inventory cannot supply it.

The existing Native transport suite covers the new exact command's forwarding and authentication/configuration holds. The Source8 suite exercises both signed artifact types through the actual immutable service and refuses invalid cut/profile/signature/deadline/original-age evidence. A source-owned pre-install observer authenticates the same signed attempt before the writer fence. Its full Native profile read captures the restored original epoch and complete control tuple; the atomic fence consumes that exact original row, with the unchanged original close deadline. The later Source8 observation must see the identical original attempt bytes and signature and match the actual installed target profile. No caller old epoch is accepted. The original mounted failures are preserved. After duplicated synchronous checks were removed without changing the five-second limit, the same two mounted cases passed 44 assertions through actual Native then DO open. The receiver permits a different original restored epoch only through private evidence minted after its original receipt MAC and actual stored physical-copy ACK; copied M17/JSON still refuses. These are local protocol mechanics, not provider-byte qualification. Physical provider execution, copy completeness and provider writer drain remain unqualified.


## Exact private release emitter and ingestion

`worker/scripts/private-release-evidence-once.cjs --check <absolute-intent.json> <sha256>` validates source/configuration/local-original pins without a provider request or secret read. Its explicit `--execute-original-once` mode uses the existing `OLYMPUS_PRIVATE_RELEASE_SIGNING_KEY` and `OLYMPUS_PRIVATE_CONTROL_AUTH_SECRET`. It authenticates the same original closing gate through the existing private `observe-cut` command before and after two read-only original Wrangler commands: `versions view <actual-version> --name olympus-verify --json` and `deployments list --name olympus-verify --json`. Both commands use the pinned existing CLI and exact frozen main configuration. The child inherits the existing Cloudflare grant, with internal control/recovery/signing secrets removed. No auth profile or credential is read by this component.

The intent names the final source freeze, exact accepted bundle, compiler/current Native/cold-bundle qualification originals, an approved binding/runtime file, the original ten-field observe-cut command and target profile. It verifies every source raw/blob/tree entry before and after observation. The approved file has schema `approved-original-worker-binding-runtime-v1` and exact account/database/worker/version/sourceTree/bundleSHA256/runtime/bindings/handlers/floorNamespaceId fields. The exact signed credential epoch, next write epoch, source tree, fixed D1 ID, admission/layout and privacy/QR flags must match the actual binding values and frozen source configuration. Binding names are unique; unknown metadata or a missing actual Floor namespace ID holds. Operator/initializer/control roots cannot be present in the serving Worker. The actual version must match all runtime, bindings and handlers, carry the source-tree tag and bundle-SHA message, and be the only latest deployment version at 100 percent. The emitter does not infer the provider ETag algorithm. Its recorded provider hashes identify the original pinned CLI JSON results after the original API response was parsed to EOF; they are not described as wire-body hashes.

The existing release authority must first approve the original accepted upload/version correlation and the exact final local qualification originals. Merely naming a local bundle, setting a version tag, or copying a qualification JSON is not upload-byte provenance. A stale snapshot's tests cannot qualify the final tree. The emitter does not sign arbitrary caller-supplied provider version/deployment JSON.

Only after these checks does it emit the existing 26-field envelope and `immutable-service-bindings.json`. Ingest its exact `PRIVACY_IMMUTABLE_RELEASE_RECEIPT`, `PRIVACY_IMMUTABLE_RELEASE_SIGNATURE` and public verification key into the existing private immutable service; the artifact lane also uses the exact two artifact receipt/signature values. These are evidence, not new roots. Every receipt retains the original close's 300-second expiry. An unfinished observation spends its release ID and stays unknown. The emitter performs no deployment, migration, restore, business write or opener call. Like the artifact component, it reports only original child closure and requires separately retained native Job containment/closure evidence.

## Installation order and production inputs

There is no outstanding guild policy choice in this procedure. Generating distinct cryptographic roots for a demonstrably fresh private Floor is authorized provisioning. Existing roots, release keys, cookie secrets, original clocks and journal lineage must not be rotated or recreated to bypass a hold. The remaining inputs are actual installation facts and evidence; no placeholder namespace ID, version, epoch, source tree, signature or receipt is a safe substitute.

| Service | Existing configuration | Required roots and bindings |
| --- | --- | --- |
| Private Floor owner | `worker/wrangler.privacy-floor.private.toml` | Own `PrivacyRecoveryFloor` SQLite class/migration `privacy-recovery-floor-v1`; three distinct roots `PRIVACY_RECOVERY_OPERATOR_SECRET`, `PRIVACY_RECOVERY_INITIALIZER_SECRET`, `PRIVACY_SERVING_GATE_SECRET`. No public routes. |
| Initializer | `worker/wrangler.privacy-initializer.private.toml` | Cross-script Floor binding; control-auth root and initializer root only; actual control source tree and its provider `CF_VERSION_METADATA`; explicit initialization-enabled value. |
| Immutable evidence | `worker/wrangler.privacy-release-evidence.private.toml` | Accepted public verification key and exact original receipt/signature, optional exact artifact receipt/signature; explicit enabled value. No D1, signer, provider credential or DO writer. |
| Operator | `worker/wrangler.privacy-operator.private.toml` | Original D1 `DB`, cross-script Floor and `PRIVACY_RELEASE_EVIDENCE` service; control-auth and operator roots only; actual current serving version/source/credential/write epochs, exact source layout/kind, Source8 enabled/configuration fields. No initializer/serving root. |
| Main serving Worker | `worker/wrangler.toml` | Private initializer/operator transport service bindings; when actually installed, all five own serving values below together. No operator, initializer, release signing or control-auth root. |

The five serving values are `PRIVACY_RECOVERY_FLOOR` (the cross-script namespace), `PRIVACY_SERVING_GATE_SECRET`, `PRIVACY_CREDENTIAL_EPOCH`, `PRIVACY_SERVING_SOURCE_TREE` and `PRIVACY_SERVING_DATABASE_ID`. They additionally require `PRIVACY_WRITE_ADMISSION_ENABLED=true`, the actual `PRIVACY_WRITE_ADMISSION_EPOCH`, correct D1 binding and actual version metadata. They are not five distinct DO services. A partial set holds; the current source configurations intentionally do not invent the missing production values. All private services currently default OFF. Erasure and beta QR stay OFF through installation qualification.

1. Freeze and qualify the actual final source/configuration/tree, proper compiler, all required current Native suites, normal scheduled graph/whole workload and exact-head CI. The earlier immutable normal-workload snapshot is evidence for its selected graph only.
2. The owner deploys the private Floor owner first, then the immutable evidence service, initializer and operator from that same qualified source. Provision the distinct roots only to the services listed above, retain the actual provider namespace/version results, and bind the canonical main transport to these exact private services. The one SQLite DO migration belongs only to its Floor owner configuration.
3. Obtain actual public-predecessor/current Native schema/control and actual writer/version/accepted-work inventory. Close external ingress/writers and retain genuine provider drain evidence for every preservation-critical origin. A fixed wait, matching captures, redeploy, or the local managed-ticket drain alone does not prove provider/all-origin drain.
4. Use the existing owner command signer to initialize a fresh Floor closed if genuinely absent. Use the original exact `close` command, then status/observe-cut to retain the same operation/Floor/Gate/deadline. Do not initialize over an existing lineage or create a new operation to retry an unknown effect.
5. For current Native installation use the existing `install-and-reopen` command. For an actual physical restore first execute the exact contained original artifact attempt, retain its provider EOF/bytes/bookmark/closure evidence, then use `install-and-reopen-artifact`. SQL import is not automatic replacement: an incompatible/nonempty target must hold; these scripts never add DROP/reset logic.
6. Publish the exact current-cut 26-field release evidence (plus artifact evidence if required) through the existing immutable service and complete within that same original 300 seconds. The actual atomic operator path then drains known managed tickets, fences the source-owned original Native tuple, installs the fixed complete profile, completes independent reservations, observes Source8, replays every authenticated selected record, ACKs the copy once, opens Native while DO is closed, completes the Native-open reserve, then opens the DO. No JSON response reconstructs a lost capability. Lost ACK remains unknown.
7. Read back actual Native profile/epoch/mode, independent completed journals/copy ACK and managed-open Floor; verify the deployed main's complete five-value binding set and original ordinary OAuth/cookie/membership routes. Physical keeper/time-travel inventory, actual stale-writer exclusion and every retained source still require their own real evidence. Do not call this all-store erasure activation from an empty/current-source install alone.
8. Enable erasure/QR only after their separate exact-source/provider/resource/all-copy acceptance. Existing local flags and `readyToReopen:false` reports remain truthful until that step.

Owner command shapes, from the checkout containing the qualified shipping commit, using its existing pinned tools (substitute only verified final paths/values; these lines have not been executed here):

```powershell
bash scripts/deploy-commit.sh $ShippingCommit --target privacy-floor
bash scripts/deploy-commit.sh $ShippingCommit --target privacy-evidence
bash scripts/deploy-commit.sh $ShippingCommit --target privacy-initializer --bind-source-tree
bash scripts/deploy-commit.sh $ShippingCommit --target privacy-operator --bind-source-tree
# Final main upload/version annotations used by the readonly evidence emitter:
bash scripts/deploy-commit.sh $ShippingCommit --tag $VerifiedSourceTree --message $VerifiedBundleSHA256 --bind-source-tree
& $Node .\worker\scripts\private-control-command.mjs --input $OriginalCommandJSON
# Append --execute-original-once only for the selected original command after its input is reviewed.
```

The existing helper exports only the selected commit with `git archive` and uses the checkout's existing local Wrangler through `npx --no-install`. Its fixed `--target` selector accepts only main (the default), privacy-floor, privacy-evidence, privacy-initializer and privacy-operator. Arbitrary configuration paths, names, environments and variables remain refused. The actual local CLI must still be the qualified `node_modules/wrangler/wrangler-dist/cli.js`, not a newly downloaded CLI.

`--tag` and `--message` are accepted only together: the tag must equal the selected commit's complete Git tree, and the message must be the separately accepted bundle SHA256. These annotations do not themselves establish upload-byte provenance. `--bind-source-tree` derives exactly one non-secret binding from that same commit: `PRIVACY_SERVING_SOURCE_TREE` for main, or `PRIVACY_CONTROL_SOURCE_TREE` for the initializer/operator. The option is refused for the Floor/evidence targets and requires the annotation pair for main. Do not put a final tree hash in its own tracked TOML; that is a self-reference. This derived binding does not select the operator's current serving predecessor, supply epochs or enable any service.

All other configuration, roots, epochs, actual provider versions, namespace IDs and original command inputs require their separately qualified installation/provisioning evidence before execution. The archived templates remain OFF and incomplete until those prerequisites are met; selecting a template is not activation authority. No remote `schema.sql`, `db:init`, ad-hoc D1 mutation, public operator URL, automatic secret rotation or new deployment helper is part of this order.

The release emitter uses `observe-cut` rather than `status` so that a genuinely fresh initializer-created CLOSED Gate is supported without replacing its original initialization digest. The source-owned observe-cut checks the same original operation/nonce/clock/next epoch and returns the actual native cut; it requires local and provider-ticket counts to be zero. The emitter never substitutes an operator-body digest for the original initializer digest.
