# Local author-signed HT1 helper

`worker/public/static/approved-guild-helper196.js` exposes only `window.OlympusApprovedGuildHelper.mount(root, {isCurrent})`, returning `{destroy()}`. Root must admit a current Admin, load the exact pinned static asset, and keep `isCurrent()` bound to that same session, route and Admin standing. Destroy the controller when that context changes. Mounting never authenticates a user or grants access itself.

The helper has no fetch, upload, storage, signing, key generation or game/provider operation. It accepts one exact HT1 string of at most 3,000 UTF-8 bytes. It neither extracts a substring nor trims, normalizes or reserializes signed material. Copy actions remain disabled until the exact original input verifies. Every edit invalidates verification; hiding, page exit and destroy clear the material and listeners. Late verification cannot restore a destroyed or superseded view.

The embedded public modulus comes from [Olympus 1.3.2 Sign.lua at d03ea8a9ce8d6d933dde9ce0f0ec7faa866a2df2](https://github.com/dnl-gentile/olympus-addon/blob/d03ea8a9ce8d6d933dde9ce0f0ec7faa866a2df2/Olympus/Sign.lua). Exact source: 8,256 bytes, SHA-256 `a38082ae3ccb7ac96bc62c49f56a0403e905baec6fb85ca460ca2f7d731d2635`. SHA-256 of the 256 raw public-modulus bytes: `bd28c005a1107d8347e752ea41b6a4ad444685e7a08949d9146d8291c96293c9`. Verification uses WebCrypto RSA-2048, exponent 3, RSASSA-PKCS1-v1_5 with SHA-256 and exactly 512 hexadecimal signature digits. This is separate from Link's Ed25519 or bot signing keys. No private key is needed or accepted.

Header parsing follows `Workshop.TakeTitles`: `HT1~timestamp~realm-group~0-or-1~entries~signature`. The plain-text preview shows the signed timestamp, realm group, public-display flag, department/member/title entries and faction-specific `^guilds^Alliance^...` / `^guilds^Horde^...` entries. It observes upstream preview bounds (8 named departments, 30 distinct department members, 20 approved guilds per faction and upstream UTF-8/name byte limits). Opaque extension entries and the exact raw signed entry field remain visible; a bounded preview is not a full interpretation of all upstream authority extensions or the addon's effective configuration. Unsafe numeric timestamps or non-roundtripping UTF-8 are refused locally instead of displayed imprecisely.

The two explicit clipboard actions copy the exact verified blob and `/oly approved paste` separately. The latter command opens the upstream paste dialog; `paste <blob>` is not its command grammar. The addon still checks its local realm group, its previously held list timestamp and authority state. Those are unknown to this helper. A valid author signature, a clipboard copy and a later-looking timestamp do not establish current author approval, freshness or successful in-game application. There is no automatic retry, publication or activation.

Root owns app/router admission, loader and asset pins. The helper uses normal panel, label, textarea, action and status elements without inline styles, HTML parsing or script/style creation. If needed, Root's scoped stylesheet should give `.approved-guild-helper196` `min-width:0`, its textarea `width:100%;max-width:100%;box-sizing:border-box`, and its preview paragraphs `overflow-wrap:anywhere` so long signed text cannot stretch the Admin layout. No additional external resource is needed.

The focused test loads the actual browser module. Its private test VM instrumentation exposes the otherwise unexported verifier to an existing [public NIST RSA-2048/e=3/SHA-256 verification vector distributed with pyca cryptography 46.0.3](https://github.com/pyca/cryptography/blob/46.0.3/vectors/cryptography_vectors/asymmetric/RSA/FIPS_186-2/SigVer15_186-3.rsp); only public modulus, message and signature are included. The vector source SHA-256 is `dd8de3c0920e3b75059491e9c5d84f2e399b2a652869977eeb863489eb7dd151`. No production key override, signing operation or private key exists. Real WebCrypto verifies that public vector and refuses tampering and wrong-key cases. Separate, explicitly mocked verifier-result cases exercise the successful UI/clipboard lifecycle because no authentic author-signed HT1 fixture was supplied. Genuine positive Olympus HT1 protocol acceptance and real addon application therefore remain pending; synthetic RSA and UI results do not replace them.
